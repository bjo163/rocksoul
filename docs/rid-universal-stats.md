## 1. Model and non-overlap rule

The 99 domains are 99 first-class peers. There is no canonical nine-domain parent taxonomy and no fixed 11-per-category grouping. Each domain has one stable `rid_domain:NN` ID and exactly one linked `rid_stat:NN` dimension. This one-to-one link represents **99 capability dimensions, not 198**: the domain defines what is measured; the linked stat is the per-profile slot that stores the score, confidence, evidence, and evaluation state. It is not a second capability construct.

Capabilities can interact in real tasks. Therefore, **non-overlap does not mean capabilities never correlate**. It means each score has one declared primary measurement target, explicit inclusion/exclusion criteria, and a boundary rule against adjacent constructs. The same success/failure signal must not be counted twice. One task may inform multiple scores only when it yields separately observable outcomes, separately referenced evidence, and separate rubric checks.

If an evaluator cannot reliably distinguish two outcomes, both dimensions remain `unrated` until the rubric is refined. Do not force a score merely to fill a profile.

## 2. Universal applicability

The taxonomy is designed for humans, AI systems, robots, software agents, and other evaluable entities, but not every dimension applies to every entity. Applicability depends on actual modality, tools, embodiment, permissions, and deployment configuration. A text-only system may mark auditory perception `not_applicable`; it must not receive zero for lacking a microphone.

## 4. Explicit overlap policy

The catalogue declares **322 directed adjacency/overlap guards forming 161 reciprocal pairs**. The second-pass review added 12 adjacent-construct guards that were not explicit in the first graph: READ/UNDERSTAND, READ/TRANSLATE, TRACK/DIALOGUE, RETAIN/ADAPT, LEARN/INTEGRATE, OPTIMIZE/ITERATE, COMPLETE/SELF_CHECK, EXPRESS/STRUCTURE, TRANSLATE/TUNE, BOUNDARY/SECURE, SECURE/RESIST, and GOAL_TRACK/HANDOFF. A third-pass semantic review added 12 further guards: NOTICE/ERROR_DETECTION, TRACK/MONITOR, TRACK/GOAL_TRACK, UPDATE/SYNTHESIZE, ANALYZE/REFLECT, PRIORITIZE/ESCALATE, EXECUTE/TRANSFER, EXECUTE/MONITOR, ALIGN/VIEWPOINT_MODEL, ALIGN/INCLUDE, INVENT/REFRAME, and EXPERIMENT/REFLECT. The JSON also contains a canonical pairwise contrast registry (`rid_overlap:001`–`rid_overlap:161`): each pair records both domain labels, both primary measurement targets, and an explicit rule for scoring them separately. These are not parent-child relationships; they identify where evaluators must distinguish nearby constructs. The runtime validator checks the declared counts, reciprocal symmetry, sorted/unique adjacency lists, unique domain and stat labels/keys, unique measurement targets, 99 distinct domain-specific separation rules, and exact parity between the adjacency graph and all 161 pairwise contrast records. These checks validate catalogue integrity; they do not prove psychometric independence.

The three modality-specific constructs **Visual Perception (01)**, **Auditory Perception (02)**, and **Sensor Input (04)** intentionally have no overlap edges: their primary input modalities and ground-truth channels are disjoint in this taxonomy. A multimodal task may evaluate more than one only when it supplies separate modality-specific observations and rubrics. Their isolation is not an omission or a claim that all real-world perception systems are statistically independent.

High-risk boundaries that must use separate outcome measures:

- **Memory:** episodic encoding/reconstruction (12), direct recall from a cue (13), delayed retention/decay (14), targeted search over a collection (19), and consolidation/deduplication (21) are different tasks. A correct answer alone cannot score all five.
- **Understanding and reasoning:** contextual interpretation (11), conceptual model fidelity (23), one-step entailment (24), multi-step derivation (25), and problem diagnosis (27) require different ground truth.
- **Analysis and judgment:** pairwise comparison (26), problem diagnosis (27), rubric-based evaluation (31), and final choice (32) must be measured separately.
- **Planning and execution:** priority ranking (33), plan feasibility (34), goal decomposition (35), dependency ordering (36), authorized start (37), task actions (38), tool protocol use (39), independent result verification (40), and deliverable presence (44) are distinct checkpoints.
- **Safety:** policy interpretation (56), ownership/scope boundary handling (57), consent/authorization validation (60), technical sandbox containment (61), attack resistance (62), audit trail (63), escalation (64), rollback (65), and refusal behavior (66) must not share one generic safety score.
- **Creativity:** possibility exploration (67), explicit candidate production (68), solution architecture (69), and novel method invention (70) are distinct novelty/utility tests.
- **Metacognition:** checklist self-review (80), defect detection (81), assumption labeling (82), uncertainty detection (79), confidence calibration (78), process monitoring (83), drift detection (87), and post-task reflection (85) use different evidence.
- **Collaboration:** active listening (50), viewpoint representation (89), shared-goal tracking (90), multi-party coordination (92), cooperative contribution (93), interaction repair (95), negotiation (97), and work handoff (98) must be tested at their respective interaction boundaries.

## 5. Scoring and evidence contract

- Initial state: `unrated`; never infer scores from XP, level, uptime, message volume, self-report, or model confidence alone.
- Score range: 0–100; confidence range: 0–100.
- Each rubric must use versioned held-out tasks, explicit ground truth or acceptance criteria, negative/control cases, sample count, evidence references, evaluator identity, timestamp, and rubric version.
- Minimum sample policy defaults: 20; safety-sensitive evaluations: 30. These are policy defaults, not proof of statistical validity.
- The evaluated entity cannot authorize its own score. A trusted evaluator must issue the result.
- `not_applicable`, `unrated`, and measured score zero are distinct states.
- XP, Level, Age, identity, capability scores, consciousness, personhood, and spiritual worth are independent concepts.

## 6. Compatibility and runtime migration

The prior `data/rid/universal_stats.v1.json` is a historical nine-group × eleven-stat catalogue. It is superseded and must not be used as a current parent-domain hierarchy. The current v2.3.3 taxonomy preserves the 99 stable ordinal stat slots but revises labels and construct boundaries; consumers must bind by explicit IDs, never by display text or inferred meaning.

**Runtime migration implemented on main; exact-head CI verification pending:** `src/rid_catalogue.rs` now embeds `data/rid/universal_stats.v2.json`; `StatId` emits `rid_stat:NN`; CLI and Cockpit render universal domain labels and construct boundaries rather than Asmaul Husna names.

It explicitly refuses to overwrite a different existing legacy archive. No ordinal score mapping is performed because old scores were evaluated under different constructs.
